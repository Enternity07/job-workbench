# 项目面试讲解

下面是理解项目的参考，不要把尚未实际完成的操作说成已完成。

## 项目解决什么问题

求职时，经常需要反复检查岗位要求、修改简历，并记住投递到哪一步。这个练习项目把岗位文字对照、投递记录和面试练习放在一个本地界面里。

## 为什么先选这么小的范围

目标公司公开业务涉及简历和求职服务。做一个相关的小工具，方便展示对场景的理解，也能练习完整的页面、接口与数据保存过程。先验证完整流程，再考虑加模型或复杂框架。

## 数据从哪里来 怎么流动

用户在浏览器输入 JD 和简历，JavaScript 用 fetch 发 JSON 给 `/api/analyze`。Python 调用 `compare` 对照内置技术词表，返回关键词、原文证据和练习题。页面用这些结果更新显示。

新增投递时，数据发往 `/api/applications`，服务端校验字段和日期，再通过参数化 SQL 保存进 SQLite。重新打开页面时，前端重新请求记录，所以刷新后仍能看到。

## 这个项目里的 AI 在哪里

Codex 辅助生成代码。应用运行时没有调用大模型。关键词覆盖率只反映文字提及，无法判断真实能力、否定语义或录用概率。下一步若接 LLM，应先定义结构化输出、核对原文、处理错误和成本，并保护个人信息。

## SQLite 和 Git 分别是什么

SQLite 是本地文件数据库，保存用户实际新增的投递数据；Git 是代码版本管理工具，用于记录修改。它们解决的问题不同。数据文件已加入 `.gitignore`，分享作品时仍应检查分享内容。

## 你本人做了什么

据实回答。当前可确认的是：以自己的求职需求提出项目方向，借助 Codex 准备作品。只有亲手运行、修改和验证后，才能补充相应经历。推荐记录一次界面改动、一次规则改动和一次报错修复，作为个人贡献的证据。

## 如果面试官让你现场改

先确认想改什么、输入输出是什么，再定位文件。界面文案在 `static/index.html`；颜色在 `style.css`；关键词与题库在 `workbench/analysis.py`；数据校验在 `storage.py`；路由在 `app.py`。不确定时可以使用 AI 工具，但要能解释改动和验证结果。
