# 从零复现求职工作台

先完成第一轮实际操作，再决定简历中可以写哪些内容。遇到报错时，把完整报错交给 Codex，让它解释原因和修改位置；保存问题与修复过程。

## 第一步 启动和使用

双击项目目录的 `start.cmd`。看到命令行中的本地网址后在浏览器打开。若 Python 不可用，先解决安装或运行环境问题；这一步完成前，不要对外说自己已经部署成功。

点“载入虚构示例”，然后“开始对照”。观察文字覆盖率，展开原文证据，再进入面试练习。示例简历是演示材料，不能当成自己的简历发送。

新增一条公司名为“演示公司”的记录，把岗位写成“测试岗位”，设置一个跟进日期，保存、修改状态、搜索、筛选，最后刷新页面确认数据仍在。完成后删掉演示记录。

你应能解释：浏览器是界面，Python 处理请求，SQLite 是本地数据库。项目不是调用模型生成答案的 AI 服务；Codex 是辅助开发它的工具。

## 第二步 做一个能看见的修改

1. 找到 `static/index.html` 中的“下一步，从看懂岗位开始。”。
2. 改成你自己喜欢的标题，保存文件，刷新页面。
3. 截一张修改前、修改后的图，写下文件名、修改内容、验证方式。

然后尝试修改 `static/style.css` 中的 `--green` 色值。每次只改一处，保证改完还能正常操作。

## 第三步 改一点逻辑

在 `workbench/analysis.py` 的 `SKILLS` 字典中增加你想支持的技能。例子：

```python
"Rhino": r"(?<![a-z0-9])rhino(?![a-z0-9])",
```

Rhino 只是适合建筑学习场景的练习词，不代表你已经会使用它。保存后重启 Python，再在岗位描述和简历里分别输入包含或不含该词的句子，检查结果如何变化。

在 `tests/test_workbench.py` 的 `AnalysisTests` 里加一个测试：

```python
def test_rhino_keyword(self):
    self.assertIn("Rhino", extract("需要 Rhino 基础"))
    self.assertNotIn("Rhino", extract("Rhinoceros"))
```

运行 `python -m unittest discover -s tests -v`。第二个断言用于检查关键词边界，避免把长词中的一部分当作技能。完成新增规则后测试数会从 15 变为 16。

复制下面的记录，每完成一次再填写。空白代表尚未完成，不要预先填写成功。

```text
实际操作日期：
这次要解决的问题：
向 Codex 提出的需求：
我亲自修改的文件和内容：
运行命令和实际结果：
遇到的报错或限制：
怎么确认修改有效：
对应截图或提交：
仍然解释不清的内容：
```

如果使用 Git，先看 README 和 `.gitignore`；不要提交数据库、联系方式、简历或导出的个人记录。可以只分享源码目录和使用虚构数据录制的演示。

## 第五步 录一段两分钟演示

前 20 秒讲用途：这是一款给实习求职者用的本地工具，把岗位要求、简历文字和投递进度放在一起。

接下来演示对照与证据、修改一条投递记录并刷新、查看面试练习。最后展示你自己改过的标题或规则，说明当前仍是离线规则版。

这套演示讲顺之后，再把实际完成的步骤补进简历。招聘方如果追问技术细节，坦诚说明自己是入门者、代码由 AI 辅助生成，以及哪些部分已亲自验证。
